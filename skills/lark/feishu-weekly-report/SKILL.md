# 飞书周报生成

## 目的

通过 lark-cli 读取用户本周飞书聊天记录，归纳实际工作内容，输出可直接提交的中文周报。

## 使用时机

- 用户要求整理/生成周报（默认统计当前自然周：周一 00:00 至当前时间，Asia/Shanghai；用户指定日期范围时以指定为准）。
- 定时自动化触发（如每周五 17:00）。

## 执行流程

### 1. 检查登录态

运行 `lark-cli auth status --json --verify`，确认 user 身份 verified，记录 openId 与 userName。未登录则提示用户先完成 `lark-cli auth login`，停止。

### 2. 计算时间范围

- 默认：本周一 00:00:00+08:00 至当前时间（或周日 23:59:59+08:00）。
- 用 shell 的 date 命令计算周一日期，不要手算。注意 Windows Git Bash 的 `date -d "last monday"` 在周一会返回上周一，需用 `date +%u` 判断星期几后自行推算。
- **边界情况**：周一早晨运行时本周窗口只有几小时，经常拉不到任何消息（chats=0）。此时不要输出空周报，应向用户确认后改拉上一完整周（上周一 00:00 ~ 上周日 23:59:59）。

### 3. 拉取消息

运行脚本（Python 3.11 系统解释器即可，无第三方依赖）：

```bash
"C:\Program Files\Python311\python.exe" scripts/fetch_messages.py \
  --start "<周一>T00:00:00+08:00" --end "<截止>T23:59:59+08:00" \
  --outdir "<工作目录>/msgs"
```

脚本行为：遍历活跃会话（自动跳过名称含"助手/机器人/CLI/汇报"等的会话与自聊）、逐会话分页拉全时间范围内消息、输出：
- `mine.txt` — 我发的消息 + @我的消息（按会话分组），**分析时先完整读这个**
- `digest.txt` — 各会话摘录（>100 条的群只保留我/@我/关键词消息）
- `summary.txt` — 各会话消息量

注意：账号无 `search:message` 权限，不要用全局消息搜索接口；飞书"汇报"应用无开放 API，不要尝试直接写入汇报表单。

### 4. 分析归纳

- 先通读 `mine.txt`，再按需回查 `digest.txt` 中相关会话的上下文（重点：发版群、测试组群、各产品线群、高频单聊）。
- 按工作主题归类，不按时间流水账。主题优先级：发版与上线协调 / 测试任务推进 / 缺陷与专项问题 / 需求评审与排期 / 环境与发布保障 / 跨团队协调 / 数据分析 / 团队建设与AI落地。
- 只写有聊天记录证据的事实；区分"已完成 / 推进中 / 待跟进"；协调、跟进、安排类不要写成"完成开发"。
- 机器人通知群（云效合并通知、RPA 告警）仅作背景，不单列。

### 5. 输出周报

- 排版严格遵循 `references/report_style.md`（用户历史周报风格：一、二、三主题分节 + 短句罗列无编号、下周计划简写、需要协调与帮助常留空）。
- 交付到 `_workspace/_active/weekly_report_<YYYYMMDD>/周报_<YYYYMMDD>.md`，并用 present_files 呈现。
- 文末附"来源会话"列表（会话名即可，不展示消息 ID；token、密码、一次性链接等敏感内容绝不写入，只概括用途）。
- 同时在回复中内联给出全文，方便直接复制到飞书汇报表单。

## 已知环境细节

- Windows 下 Python subprocess 调 lark-cli 必须用 `lark-cli.cmd` 完整路径 + `shell=True`（脚本已内置）。
- 消息接口返回字段是 `data.messages`，分页字段 `has_more` + `page_token`。
- 含 openpyxl 的解释器是 `C:\Program Files\Python311\python.exe`；管理的 3.13 无第三方包。

# 周报写作风格（用户历史周报确认版）

## 结构

三个字段，对应飞书"汇报"表单：

1. 【本周工作】
2. 【下周计划】
3. 【需要协调与帮助】（通常留空或一两句）

## 主题分节（2026-08-28 用户确认版，优先使用）

固定五个主题，无内容的小节可省略：

1. 税务专项与发票采集
2. 测试任务推进
3. 安全测试发现与推进
4. 性能与体验
5. 团队建设与AI落地

下周计划对应分节：税务专项 / 测试任务推进 / 团队建设与AI落地（内容少时可合并）。

## 本周工作写法

- 用"一、二、三…"主题分节，每节一个主题（如：发版与上线协调 / 测试任务推进与人员协调 / 缺陷与专项问题 / 测试环境与团队建设 / 评审与测试管理 / AI落地推进 / 接口自动化测试）。
- 每节下面是短句罗列，一句一条事实，**不用 1.2.3. 编号**，不用加粗、不用表格。
- 句式以动词开头：协调 / 跟进 / 安排 / 组织 / 推进 / 输出 / 完成 / 验证 / 处理。
- **同一主题下的零散动作要收敛概括**：围绕同一专项的会议、验证、统计输出等，合并为 1~3 条"干了哪几件事"的概括句，不要逐日逐条流水账（用户明确反馈过：7 条税务动作"总结下来其实就两件事"）。发版协调类内容压缩到 3 条以内、每条 30 字左右，日期和"知晓/注意"类弱动作可省略。
- 涉及日期写"7月28日"格式；涉及人员直接写名字；缺陷写编号（BMGT-xxx）。
- 严格区分"已完成 / 推进中 / 待跟进"；协调类工作不写成"完成开发"。
- 长度参考：5~6 个主题，每主题 3~6 句。

## 下周计划写法

- 短句罗列，一般不分节（内容多时可分节），3~6 句。
- 用户偏好：按下周任务所属业务线/大类分节（如：税务专项 / 上线与测试任务推进 / 团队建设），与"本周工作"的主题分节结构一致（2026-08-10 反馈）。
- 来源：本周未闭环事项 + 已确认的下周评审/提测/上线计划，不虚构。

## 需要协调与帮助写法

- 用户历史周报大多留空。只有确实存在跨部门阻塞事项时写 1~2 句。

## 历史样例（2026-07-25 提交，节选）

```
一、税务专项与票税/发票采集跟进
参与处理"税务解绑公司导致频繁切换公司后登录状态失效"问题，配合相关人员沟通税局防 RPA 机制带来的影响。
协调蒲波、周杰参与税务重新测试，提醒如工作量较大及时补充测试资源。
编写并同步发票采集、票税登录相关统计 SQL，用于按办税员账号统计采集状态。
二、CRM 数据统计专项推进
跟进 20260717 CRM 数据统计专项，安排张霖湘、蒲波、周杰、徐浩验证问题。
```

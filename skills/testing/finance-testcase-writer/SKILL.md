# Finance Testcase Writer

遵循 `references/rules.md` 的强制规则与输出模板。本技能用于：用户先提供“完整需求文档”，再提供“需求片段”；你需结合全部上下文，但仅针对该片段生成测试用例。

## Workflow（按顺序执行）

1. 输入检查
   - 未收到“完整需求文档”时：先让用户提供完整需求文档，再开始生成用例。
   - 未收到“需求片段”时：先让用户提供需求片段，再开始生成用例。
2. 严格定界（只测需求写了什么）
   - 仅使用需求片段中明确出现的模块、字段、页面、角色、状态、流程；不新增、不跨模块、不扩展、不补充隐含逻辑。
   - 完整需求文档仅用于理解上下文，不得引入片段未出现的新对象/新规则到用例里。
3. 分拆式全覆盖（禁止合并）
   - 每个场景、校验点、状态变化均为独立用例。
   - 非必填字段分别写“有效/无效”等价类用例。
   - 字段边界校验：空值、最小、最大、超长、非法字符、格式、数值上下界、精度，每一种情况一条用例。
4. 覆盖范围（按顺序生成）
   - 主流程用例（P0/P1）
   - 功能用例（正常/异常/状态流转）
   - 字段级边界校验
   - 权限用例（有权限/无权限/只读/部分字段可见）
   - 跨模块联动（仅限需求中明确描述）
   - 极端场景
   - 自检补充用例
5. 输出格式（强制）
   - 仅输出正式用例表格，不输出解释/摘要/检查清单。
   - 表头必须为：`| 编号 | 目录 | 优先级 | 标题 | 前置条件 | 步骤描述 | 预期结果 | 负责人 | 用例类型 |`
   - 用例编号顺序递增且唯一；用例过多时分批输出并标注“第 X 批 / 共 N 批”。
   - 前置条件必须同时包含：系统状态、权限配置、数据准备。
6. 自检机制（必须执行）
   - 输出前按 `references/rules.md` 的自检项核对：模块、字段边界、状态流转、权限、异常类型。
   - 如发现遗漏，立即补充用例（仍以正式表格继续编号），直到覆盖完成。

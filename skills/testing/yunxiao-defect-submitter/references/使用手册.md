# 云效提缺陷工具 · 使用手册

> 面向测试团队。三种用法：**发截图给 AI 自动写缺陷单**、命令行提单条、Excel 批量导入。
> 以下命令均在工具包根目录（SKILL.md 所在目录）执行；首次使用把工具包发给 AI Agent，Agent 会按 SKILL.md 自动完成安装和配置。

---

## 一、快速上手（推荐用法）

**把 bug 截图 + 一句话描述发给 AI 助手（Kimi / Codex）即可。**

提缺陷分两种场景，AI 会自动判断（也可你直接说明）：

| 场景 | 你说什么 | AI 怎么处理 |
|---|---|---|
| A. 日常迭代提缺陷（默认） | 「[截图] xxx 有问题，提个缺陷」 | 按【缺陷报告模板】生成：标题/模块路径/复现步骤/实际结果/预期结果，步骤带具体输入数据，描述准确可定位 |
| B. 用户反馈的 bug | 「这是用户反馈的 bug，原样提上去」 | 描述保持原文不改写，只提炼标题；批量清单会先给你确认条数和跳过项 |

流程：AI 生成草稿 → **给你确认** → 创建到云效并把截图贴进描述。

示例对话：

> 你：「[截图] 客户管理联系人维度，VIP1~4 筛选数量加起来比全部还多，提个缺陷」
> AI：（返回模板草稿：标题/复现步骤/实际结果/预期结果/负责人安家星/验证者蒲波/严重/高）
> 你：「没问题」
> AI：「已创建，缺陷ID xxx，请到云效核对」

你可以在描述里补充指定：模块、负责人、验证者、严重程度、提到哪个项目（CRM/税务/需求池），AI 会按你指定的来。

## 二、首次使用前的一次性配置

| 步骤 | 操作 | 说明 |
|---|---|---|
| 1 | 申请个人令牌 | 云效 → 个人设置 → 个人访问令牌 → 新建，勾选「项目协作」读写权限，得到 `pt-` 开头令牌 |
| 2 | 填 scripts/config.json | 把令牌填入 `token`；`default_assignee` 填自己的 userId（可让主管帮忙查） |
| 3 | 确认项目权限 | 确保自己已加入目标云效项目（01【CRM】/02【税务】/生产环境问题与需求池） |
| 4 | 维护人员映射 | 在 `scripts/模块人员映射.csv` 里维护你负责模块的负责人/验证者 |

`scripts/config.json` 含个人令牌，**不要发群里、不要提交 git**。

## 三、命令行用法

运行环境已自带（`.venv`），无需装任何东西。

### 1. 单条创建

把缺陷内容写成 JSON（字段见下），然后：

```bash
.venv/Scripts/python.exe scripts/create_bug.py --file bug.json                          # 默认提到 01【CRM】
.venv/Scripts/python.exe scripts/create_bug.py --file bug.json --project "02【税务】"
.venv/Scripts/python.exe scripts/create_bug.py --file bug.json --project "生产环境问题与需求池"
.venv/Scripts/python.exe scripts/create_bug.py --file bug.json --dry-run                # 只预览不创建
```

bug.json 字段：

| 字段 | 必填 | 说明 |
|---|---|---|
| title | 是 | 缺陷标题，建议 `【模块】问题概述` |
| steps | 是* | 复现步骤，字符串数组 |
| actual | 是* | 实际结果 |
| expected | 是* | 预期结果 |
| description | 否 | 成品描述原文；填写后替代 steps/actual/expected（用户反馈 bug 原样提交时用） |
| images | 否 | 截图本地路径数组，创建后自动贴进描述 |
| severity | 否 | 致命/严重/一般/轻微/建议，默认「一般」 |
| priority | 否 | 紧急/高/中/低，默认「中」 |
| assignee | 否 | 负责人姓名（自动解析 userId，查不到会提醒） |
| verifier | 否 | 验证者姓名 |
| module | 否 | 模块名，写入描述 |

*填了 description 时 steps/actual/expected 可不填。

### 2. Excel 批量导入

1. 在 `scripts/缺陷导入模板.xlsx` 对应模块 sheet 按行填缺陷（**缺陷标题必填**）
2. 预检：`.venv/Scripts/python.exe scripts/import_defects.py --dry-run`
3. 正式导入：`.venv/Scripts/python.exe scripts/import_defects.py`
4. 结果回写在每行「导入状态」列（成功含缺陷ID）；**已成功的行再跑会自动跳过**，可反复执行

### 3. 联调辅助（管理员用）

```bash
.venv/Scripts/python.exe scripts/probe_fields.py types    # 列项目的工作项类型
.venv/Scripts/python.exe scripts/probe_fields.py fields   # 查缺陷类型的字段和选项ID
```

## 四、模块人员映射表（scripts/模块人员映射.csv）

格式：`项目,模块,负责人,验证者`

```csv
项目,模块,负责人,验证者
01【CRM】,客户管理,安家星,蒲波
01【CRM】,工单管理,杨洪钢,徐浩
02【税务】,发票采集,刘远锐,何祥
,通用模块,默认负责人,默认验证者
```

- 「项目」对应 scripts/config.json 里的 `project_name`；留空 = 所有项目通用兜底
- 「模块」按关键词模糊匹配，写一级模块名即可
- 换人/换模块归属时直接改这个文件，即时生效，不用改代码

## 五、常见问题

| 问题 | 处理 |
|---|---|
| 提示 token 无效/401 | 令牌过期或被撤销，重新申请填入 scripts/config.json |
| 负责人解析失败 | 检查姓名是否写对（如「杨洪钢」不是「杨洪刚」）；解析失败的字段会留空，创建后在云效手动分配 |
| 创建报字段错误 | 项目字段配置变了，跑 `scripts/probe_fields.py fields` 把最新 fieldId/选项ID 更新到 config.json 的 field_map（找主管） |
| 目标项目没有「缺陷」类型 | 该项目停用了缺陷类型（如需求池只有「线上故障」），换类型或联系项目管理员启用 |
| 截图没贴进描述 | 只有走 scripts/create_bug.py / AI 提单才会贴图；Excel 批量模板不带图 |
| 提错了项目/提重复了 | 云效回收站可恢复；重复的单子在云效里删除即可，删除只进回收站 |

## 六、提单质量约定（部门统一）

1. **标题**：`【模块-子模块】什么对象 + 什么现象`，数据类问题带关键数值
2. **复现步骤**：账号角色（总部/分公司）+ 入口菜单 + 操作对象，一步一个动作
3. **预期/实际**：一一对应，数据类给出正确值、错误值和差值
4. **截图**：能截全页面关键信息（含 URL/菜单路径），脱敏客户敏感信息
5. **严重程度**：主流程阻断=致命；核心功能/数据错误=严重；普通功能问题=一般；UI文案=轻微
